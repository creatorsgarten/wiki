# AI ทำให้การเขียนโค้ดถูกลง แต่ Architecture ที่แย่ ทำให้คุณจ่ายแพงขึ้น
:::

โค้ดที่อ่านยากยังพอแก้ได้ แต่เมื่อขอบเขตของระบบไม่ชัดเจน Dependencies พันกันยุ่งเหยิง และ Components เชื่อมโยงกันแน่นเกินไป การเปลี่ยนแปลงเล็ก ๆ เพียงครั้งเดียวก็อาจกลายเป็นปัญหาลูกโซ่ได้

เพราะบางครั้ง ปัญหาไม่ได้อยู่ที่โค้ด แต่อยู่ที่ Architecture เบื้องหลังมันต่างหาก

มาร่วมงาน **Software Architecture Meetup 2026** เพื่อสำรวจ 3 มุมมองที่ Software Engineer ไม่ควรมองข้าม

### 01 — Redproof, Anti-Rot: Gate What You Care

เราจะออกแบบกลไกป้องกันสิ่งสำคัญในระบบได้อย่างไร? มาทำความเข้าใจแนวทางป้องกัน Codebase ไม่ให้เสื่อมสภาพไปตามกาลเวลา จนทุกการเปลี่ยนแปลงกลายเป็นความเสี่ยง

### 02 — Applying Category Theory with Domain-Driven Design

จะเกิดอะไรขึ้นเมื่อ Category Theory มาพบกับ Domain-Driven Design? มาสำรวจว่าการคิดเชิงคณิตศาสตร์จะช่วยเปิดมุมมองใหม่ในการออกแบบซอฟต์แวร์ การสร้าง Domain Model และการจัดการความซับซ้อนของระบบได้อย่างไร

### 03 — Extreme Discussion

ร่วมพูดคุยแลกเปลี่ยนมุมมองกับแขกรับเชิญเกี่ยวกับอนาคตของ Software Architecture ผ่านประสบการณ์จริง ตั้งคำถามกับแนวคิดเดิม ๆ และสำรวจทิศทางของ Software Engineering ในยุคที่ AI กำลังเปลี่ยนวิธีการพัฒนาซอฟต์แวร์

ไม่ว่าคุณจะเป็น Software Engineer, Backend Developer, Tech Lead, QA Engineer, System Architect, SRE หรือคนที่ต้องรับผิดชอบการสร้างและดูแลระบบในระยะยาว งานนี้มีเรื่องให้คุณกลับไปคิดต่อแน่นอน

**มาร่วมแลกเปลี่ยนมุมมอง แล้วกลับไปสร้างซอฟต์แวร์ให้ดีกว่าเดิม ไม่ใช่แค่กลับไปเขียนโค้ดแบบเดิม ๆ**
